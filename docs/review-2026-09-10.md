## Assessment

The static HTML/ES module architecture, centralized SoQL queries, route-borough constraints, and historical/current split are appropriate. No evidence of incorrect reference totals, cross-borough query leakage, injected HTML from data, added credentials, or an unintended production deployment was found. This is a focused review, not a guarantee that every possible filter combination or source-data anomaly is correct.

There were meaningful interaction and presentation defects that should be corrected before merging. The original 24 passing tests did not exercise dashboard-controller behavior. The cleanup adds those regression cases without a build system or runtime dependency.

## Findings and fixes

| Impact | Submitted behavior | Local correction |
| --- | --- | --- |
| High | Clearing a date threw `RangeError` while rendering the summary, before validation and cancellation could run. Reproduced in Chrome. | Incomplete dates remain renderable; validation explains the problem and obsolete work is cancelled. |
| High | Filter changes left old requests running throughout the debounce interval. Panel rendering lacked a final generation/signal guard. An immediate identical restart could reuse an already-aborted request. | Cancel on selection changes, mark previous results stale, reject obsolete renders, and start a fresh fetch when the previous one was aborted. Late cancelled responses cannot overwrite the cache. |
| Medium | Zero-request days/months were absent from line-chart axes, compressing gaps and hiding zero intervals. | Include eligible calendar intervals, fill missing values with zero, and preserve entirely empty states and selected-year constraints. |
| Medium | The board chart silently discarded everything after the first 15 board values, affecting Bronx, Brooklyn, and Queens. | Retain all returned board totals. |
| Medium | Address search could not find a normal-space spelling copied from the rendered table when the source stored repeated spaces. | Match search tokens across whitespace while retaining the exact source spelling for selected-address filters. Verified with `48 WEST   68 STREET`. |
| Medium | Cached results never expired within an open page, despite the live-data wording. | Five-minute expiry without background polling; cache hits do not extend the expiry. |
| Medium | Replacing filter checkboxes dropped keyboard focus; reset left option-search text and pending address suggestions behind. | Restore focus to the same checkbox value and clear pending search work/text on reset. |
| Latent | Complaint comparisons omitted `$limit`. Socrata defaults to 1,000 grouped rows. Today's eight-series UI stays below that limit for the available dataset spans, but the API accepts more series and longer spans will eventually exceed it. | Size the grouped-row limit from the date buckets and requested series. Regression test exercises 1,440 rows. |

The Socrata limit behavior is documented in [the official LIMIT reference](https://dev.socrata.com/docs/queries/limit.html).

## Remaining considerations

The upstream contribution is large (roughly 7,200 added lines, plus assets), so reviewability is a real concern even though it preserves the static architecture. Avoid adding more features to this PR. Duplicated static dashboard markup is maintenance debt, but introducing a template/build system during this cleanup would expand risk.

Address/hotspot rankings spanning both datasets remain bounded candidate rankings, not guaranteed global rankings. Map points are newest-first samples, not an unbiased geographic distribution. These limits are documented and were not changed. High-cardinality optional aggregates still use fixed bounds and would benefit from explicit saturation detection in later work.

Anonymous API latency, real Firefox/Safari checks, and screen-reader testing remain release considerations. The historical performance caveats in `VALIDATION.md` still apply. Source board/borough labels are trusted as reported by NYC Open Data; this application does not independently geocode or correct them.

## Patch scope

Changes are confined to the shared API/controller/chart modules, regression tests, README/validation records, and this review. Each of the five borough HTML files and `prototype.html` only changes its dashboard script version so cached browsers receive the fixes. `CNAME`, `index.html`, styles, borough configuration, map implementation, dependencies, analytics, and deployment settings are unchanged by this cleanup. No PR comments, pushes, or deployments were made.
